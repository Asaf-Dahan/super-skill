# Example: Technical Stack Management Super Skill

This is a complete, populated example of a Super Skill for technical
stack management. It shows what a Super Skill looks like after
activation with Prompt 1 from ONBOARDING.md.

All names, companies, products, costs, and decisions in this example
are entirely fictional. They are designed to be instructive and
realistic, not to represent any real person or infrastructure.

Owner: Tomer Naveh / Raincode Labs (fictional)
Domain: AI-first solopreneur technical stack (GreenLedger + PulseLog)
Activated: April 2026

## Files in this example

All 10 layer files are populated with fictional demo data:
  CONTEXT.md       -- domain identity and operating principles
  DOMAIN_MAP.md    -- two-product architecture with shared services
  CURRENT_STATE.md -- verified stack state as of April 2026
  EVALUATION.md    -- evaluation criteria for a solo operator
  DECISIONS.md     -- 5 architectural decisions with reasoning
  MONITORING.md    -- 8 sources to watch for drift
  LEARNING.md      -- 6 planned learning modules
  PENDING.md       -- approval queue (empty at time of snapshot)
  SKILL.md         -- agent entry point for this domain
  CLAUDE.md        -- Claude Code operating instructions
  SUMMARY.md       -- 80-line session entry point

## How to use this example

1. Read CONTEXT.md to see how domain identity is defined
2. Read DOMAIN_MAP.md to see how a two-product architecture is mapped
3. Read DECISIONS.md to see how decisions are recorded with reasoning
4. Read EVALUATION.md to see criteria calibrated for a solo operator
5. Use these as reference when activating your own Super Skill
