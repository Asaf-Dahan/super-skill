# Example: Craft Domain Super Skill

Super Skill works identically for craft domains as it does for
technical or professional domains. Photography, woodworking, wine,
cooking techniques, specialty coffee, academic research -- any craft
where knowledge accumulates and decisions matter.

The layer architecture does not change. Only the content does.

---

## What a Craft CONTEXT.md Looks Like

Here is a fictional excerpt for a specialty coffee roasting domain:

```
## Domain

Specialty Coffee Roasting -- single-origin beans, home roasting setup

## Owner

Home roaster, sourcing green beans from three importers

## Goals

- Track roast profiles for every bean origin and batch
- Evaluate new green bean suppliers against quality and cost criteria
- Monitor harvest seasons and detect when a favorite origin is unavailable
- Document every roast profile decision with tasting notes
- Never commit to a new supplier without a full evaluation
```

The same structure works for any craft. Replace "coffee roasting"
with your craft and the layers fill naturally.

---

## Do You Need a Super Skill or Just a SKILL.md?

Use the three-question test from examples/tool-skill-only/:

1. Does this domain change externally without your control?
2. Are there decisions that must never be re-litigated?
3. Does your agent need verified current state before every task?

If two or more are YES: build a Super Skill.
If fewer than two: a SKILL.md file is enough.

Most craft domains score YES on all three -- suppliers change,
techniques are settled after testing, and current inventory matters.
